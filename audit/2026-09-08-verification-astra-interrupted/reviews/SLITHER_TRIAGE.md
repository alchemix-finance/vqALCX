# Static-analysis triage

The fresh [Slither JSON](/Users/deepthought/Desktop/dev/vqalcx/audit/2026-09-08-verification/evidence/slither.json) reports success and **27 detector records**. Raw detector severity is not a project finding severity. This triage inspected the flagged current source paths and did not reproduce exploit scenarios.

| Detector | Count | Reviewed disposition |
|---|---:|---|
| `incorrect-equality` | 5 | No standalone issue established. Two `elapsed == 0` checks deliberately stop same-timestamp accrual. Two `filled == amount` checks recognize exact completion after adding the minimum of remaining amount and budget. `reward == 0` rejects an empty claim. These comparisons should remain tested within accounting properties; replacing all equalities would be inappropriate. |
| `reentrancy-no-eth` | 2 | Conditional integration concern, not a demonstrated finding under the reviewed fixed vault and conventional-token assumptions. Settlement performs vault calls and writes round completion/current round afterward. `ensureDepositRound`/`ensureWithdrawRound` are unguarded, so `nonReentrant` on settlement alone does not justify blanket dismissal of cross-function callbacks. The reviewed vault calls do not invoke an arbitrary recipient hook with ordinary ERC20 behavior; callback-capable external tokens remain unsupported pending separate analysis. Treat this as part of the token callback restriction and configuration review. |
| `missing-zero-check` | 2 | The vault's initially zero auctioneer is explicitly allowed at construction and is not itself a defect. The auctioner's unchecked treasury is an actual deployment-validation gap: a zero treasury can prevent premium transfers for a standard token. Address correctness must be validated before use; see token integration evidence E6. |
| `reentrancy-benign` | 2 | The cited external call is to the auctioner's own `ensure*Round` method while the bid entry point holds the reentrancy guard. No independently demonstrated harmful reentrancy follows from this self-call. The methods read the configured vault's bucket rate through a view interface. Unknown/malicious vault wiring is excluded by required deployment validation, not by detector suppression. |
| `timestamp` | 12 | Timestamp use is required by TC-3. These taint findings do not independently show incorrect time handling. The separate runtime review must assess bid/settlement equality at end time, cumulative drip budgets, overflow bounds, and actual DAO clock compatibility. Do not replace timestamps with block numbers. |
| `missing-inheritance` | 1 | Optional interface declaration/compile-time consistency improvement. VqALCX structurally implements the auction-facing functions; lack of explicit inheritance from the interface declared in the auction file is not a demonstrated security failure. This does not resolve broader ERC4626/async compatibility questions. |
| `naming-convention` | 1 | `CLOCK_MODE()` uses the interface-mandated method name. The string it returns needs independent standards/integration review; this naming detector does not check that string. |
| `immutable-states` | 2 | `daoTreasury` and `roundDuration` are constructor-only writes and could be declared immutable. Optimization/intent clarity only; no exploitability conclusion. |

Counts sum to 27. No reported detector record was left unclassified. Manual accounting and composed-system verification remain necessary because the detectors do not establish escrow conservation, reward fairness, safe auctioneer replacement, governance delay guarantees, or queue liveness.
